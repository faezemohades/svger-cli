    Bundler and test integrations

    Use documented integration subpaths instead of running the CLI from a build hook. Integrations execute in the toolchain process; configure file scope and only load trusted plugins.

    Vite

    import { svgerVitePlugin } from 'svger-cli/vite';
export default { plugins: [svgerVitePlugin({ source: './src/icons', framework: 'react' })] };

    Webpack

    const { SvgerWebpackPlugin } = require('svger-cli/webpack');
module.exports = { plugins: [new SvgerWebpackPlugin({ source: './src/icons', output: './src/generated' })] };

    Other integrations

    Package subpaths are svger-cli/rollup, svger-cli/babel, svger-cli/nextjs, and svger-cli/jest. Confirm options and compatibility against the installed version and the full integration guide. Integrations are release-gated against the documented toolchain matrix; using a different major may work without being covered.

    Build plugins can write generated files or transform SVG imports depending on integration mode. Review source and destination paths, watch/HMR behavior, and CI permissions before enabling writes.

    Related source and version caveats: SVGER-CLI repository.
