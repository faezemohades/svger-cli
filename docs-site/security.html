    SVG input security and safe use

    SVG files are untrusted structured input. SVGER-CLI validates inputs before generation and rejects selected unsafe constructs by default. This is defense in depth, not a guarantee that arbitrary generated code is harmless.

    Default rejection

    Active content, event handlers, unsafe URI forms, malformed XML, external references, and resource-limit violations are handled by the input safety policy. Exact rules are version-specific. Keep dependencies patched and review the security design record.

    Strip mode is not a sanitizer

    --unsafe-input-policy strip explicitly removes selected constructs and warns. Stripping can change meaning and does not establish semantic safety. Reject mode is preferred for ordinary workflows.

    Paths, outputs, and plugins

    Use isolated output directories, preserve backups, and review destructive commands such as clean. Build-tool plugins and extension code run with the host process permissions. Never load untrusted code in a process with secrets.

    Report security issues

    Follow the project's security reporting policy. Do not paste credentials or sensitive exploit material into public issues.
